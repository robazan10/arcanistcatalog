# Architecture

A static catalog: product data comes from Google Drive through a script run by hand, and the site is plain files on Vercel. There's no server, database or prices.

## Data flow

```
Google Drive  My Drive/3D Arcanist/Images/<NN Type>/<Brand>/<Product>/   (meta.txt + photos)
      │   scripts/generate-manifest  (run by hand, Drive API with a service account)
      │     · type from the 1st level (number = order), brand from the 2nd, product from the 3rd
      │     · reads meta.txt and lists photos; "cover" first, then name order
      │     · checks each photo's shape against its type's frame (src/lib/photo-frames.json)
      │     · sets each photo to "anyone with the link can view" (not with --dry-run)
      ▼
arcanist-catalog/src/data/catalog.json   +   docs/catalog-status.md
      │   committed in a PR; Vercel builds main on merge
      ▼
next build (output: 'export')  →  arcanist-catalog/out/  →  Vercel  →  www.arcanistsdice.com
```

- The Drive folder layout and `meta.txt` format are in [`drive-images-schema.md`](drive-images-schema.md). The script's root folder ID is in `scripts/generate-manifest/config.json`.
- Photos are not copied anywhere: the site links to `https://lh3.googleusercontent.com/d/<file id>` and asks Google for a resized copy with `=w<width>`.
- `catalog.json` is the source of truth for the site and its git history doubles as a log of catalog changes. Each product has `id` (brand + name), `name`, `type` (type id, e.g. `figures`), `brand`, `category` (= brand, used by the chips and badges), `tags` and `images`. Top-level lists: `types` (`id`, `name`, `order`, `productIds`; the side menu), `categories` and `tags`. A catalog without `types` (made before October 2026) still works: the site shows no menu.
- `node index.js --dry-run` reads Drive but changes no sharing and writes its `catalog.json` and `catalog-status.md` to a temp folder, to compare before a real run.

## Routes

| Path | What | Source |
|---|---|---|
| `/` | Catalog in Spanish | `src/app/(es)/page.tsx` |
| `/en/` | Catalog in English | `src/app/(en)/en/page.tsx` |
| `/data/products/<id>.json` | One product's photo URLs, fetched when it opens | `src/app/data/products/[file]/route.ts` (static, one file per product) |
| `/forge`, `/forge/*` | D4 Stat Forge, a separate Vercel project | `vercel.json` redirects and rewrites. Never add files under `/forge` here |
| `/og-image.png`, `/favicon.ico`, `/icon.svg`, `/apple-icon.png` | Link preview and icons | `public/`, `src/app/` |

`trailingSlash: true` makes the build write `/en/` as `en/index.html`. The search, the selected type and the open product go in the query string (`/?q=…`, `/?type=keycaps`, `/en/?type=keycaps&q=goku`, `/?p=tanuki-gojo`).

## Code layout (`arcanist-catalog/src`)

```
app/
  (es)/layout.tsx, page.tsx      Spanish root layout + page
  (en)/layout.tsx, en/page.tsx   English root layout + page
  data/products/[file]/route.ts  per-product photo JSON
  globals.css                    Tailwind layers, brand component classes (.panel, .btn-main, .badge…)
components/
  SiteLayout.tsx                 <html lang>, header, WhatsApp bar, footer, analytics (shared by both languages)
  Analytics.tsx                  client: the Umami script (live domain only) and one page view per load
  HomePage.tsx                   loads summaries, categories and menu types, renders CatalogClient
  Header.tsx, LanguageSwitch.tsx, InstagramButton.tsx
  TypeMenu.tsx                   client: menu button in the header + side panel by type (portal into <body>)
  CTAButtons.tsx                 client: WhatsApp bar; its message follows the type (Dice has its own)
  CatalogClient.tsx              client: title per type, search, chips, grid/list toggle, filtering, URL sync
  SectionSoon.tsx                "Próximamente" notice for a menu type with no products (Dice)
  ProductCard.tsx, ProductRow.tsx, ProductModal.tsx
  icons.tsx
i18n/dictionaries.ts             every UI text in es and en
lib/
  catalog.ts                     reads catalog.json; summaries for the grid (A→Z, "Fotos pronto" last); menu types
  images.ts                      sizedImage(url, width); widths 500 / 1000 / 200; productDataUrl(id)
  search.ts                      normalize() (case + accents); ?q= read/write
  analytics.ts                   track(event, data) and trackPageView(); the events are listed in docs/analytics.md
  share.ts                       ?p= read/write; product and current-view links; shareLink(): phone share menu, else copy
  productType.ts                 ?type= read/write, the "typechange" event, COMING_SOON_TYPES (dice)
  useSelectedType.ts             hook: the type in the address, following the menu and Back/Forward
  metadata.ts, fonts.ts, config.ts (WhatsApp/Instagram links, Umami ID), types.ts
data/catalog.json                generated by the script
```

Server components render the page shell and pass plain data down. The client part starts at `CatalogClient`, which takes the language code and reads the dictionary itself (dictionaries contain functions, which can't be passed from server to client components).

## State

| State | Where it lives | Why |
|---|---|---|
| Search text | URL `?q=` | Shareable links; Back/Forward |
| Open product | URL `?p=` (replaceState, no Back step) | Product links for sharing and the WhatsApp message |
| "Enlace copiado" message | Component state in `CatalogClient` | |
| Selected type | URL `?type=`; components follow it through `useSelectedType` (a `typechange` event plus `popstate`) | Linkable sections from Instagram; the header menu, the catalog and the WhatsApp bar are separate components |
| Language | The path (`/` or `/en/`) | Separate pages for search engines |
| Grid or list | `localStorage` key `catalog-view` | A per-device preference; falls back to grid if storage is blocked |
| Selected category chip | Component state | Resets on reload and on a type change |
| Open product, expanded tags | Component state | |
| Photo lists already fetched | In-memory cache in `ProductModal` | Avoid refetching in one visit |

## Images

| Where | Width requested |
|---|---|
| Grid card | `=w500` |
| List row thumbnail | `=w200` |
| Product view | `=w1000` |
| Product view: thumbnail row | `=w200` |
| Product view: photo grid | `=w300` |

The product view and its photo grid show each photo whole (`object-contain`) in a frame shaped per type: `arcanist-catalog/src/lib/photo-frames.json` (`"figures": "4/5"`, `"keycaps": "3/2"`; other types square), read by `photoFrame()` in `src/lib/images.ts` and set as the CSS variable `--photo-frame`. The catalog script reads the same file to list photos that fit their frame poorly in `catalog-status.md`. Cards, rows and thumbnails stay square and cropped (`object-cover`).

`next/image` runs with `unoptimized: true` (static export), so resizing is entirely Google's. The grid lazy-loads; the product view shows the cover immediately, then the full list from `/data/products/<id>.json`.

## Stack

Next.js 15 (App Router, static export), React 19, TypeScript, Tailwind 3 with the brand tokens from [`brand-ui.md`](brand-ui.md), fonts self-hosted by `next/font` (Staatliches, Nunito). The script is Node with `googleapis`. Hosting: Vercel, building `main` with the command in `vercel.json`.
